# 분류 정확도 평가 (사람이 정답을 다는 방식)

목적: "PASSBOX의 C/S/O 판정이 얼마나 맞나"를 숫자로 말하기 위한 소규모 평가셋입니다.
지금 발표 자료의 38→4(근거 없는 차단 감소)는 정답 라벨이 없는 문서에서 센 것이라 정확도가 아닙니다.

## 정답 다는 법 (약 20분)
1. `candidates/doc_01.txt` ~ `doc_30.txt`는 이 평가를 위해 지어 낸 가상 문서입니다(실제 인물·번호 아님).
2. `labels_template.csv`를 `labels.csv`로 복사하고, **PASSBOX 결과를 보기 전에** `정답등급(C/S/O)` 열을 채웁니다.
   - 기준은 「국가 망 보안체계 보안 가이드라인 1.0」 표 2-8입니다.
     - **C(기밀)**: 법률상 비밀·국가 안보·국방·외교·수사 등(정보공개법 제9조 제1~4호)
     - **S(민감)**: 개인정보·감사/인사·영업비밀·로그 등
     - **O(공개)**: C·S가 아닌 모든 정보
   - 애매하면 메모 열에 이유를 적고, 가능하면 두 사람이 각자 달아서 다르면 의논합니다.
3. 팀원 두 명 이상이 따로 달면 더 믿을 만합니다(서로 다른 부분은 발표에서 "라벨러 간 불일치"로 솔직히 보여 줄 수 있습니다).

## 채점
```
cd backend
python evaluation/classification_eval/run_classification_eval.py
```
분류 서비스(8100)가 떠 있어야 합니다. 모델 단독과 하이브리드(실제 서비스와 같은 보정)를 나란히 보여 주고,
**실제보다 낮게 판정한 위험한 오류**와 **과잉 통제**를 따로 셉니다. 결과는 `result.json`에도 저장됩니다.

## 해석할 때 주의
- 30건은 작아서 "정확도 ○○%"를 일반화할 수 없습니다. 발표에서는 "30건 소규모 평가, 한계 있음"이라고 같이 말하세요.
- 가상 문서라 실제 업무 문서의 분포를 대표하지 않습니다.
- 정답을 달기 전에 `--predict`로 결과를 먼저 보면 라벨이 오염됩니다.
