3. 오늘 새로 발견/수정한 버그: 청크 경계 분리로 인한 탈문맥 오분류

이건 데이터셋/학습 문제가 아니라 classifier-service/app.py의 청크 분할 로직 버그입니다. 재학습과 무관하게 코드만 고치면 되는 부분입니다.

3-1. 증상

작품설명서.docx는 v2 모델로도 여전히 S로 오분류됨. 512토큰 제한 때문에 문서가 3개 구간(청크)으로 쪼개지는데, 마지막 청크가 216자(토큰 100개)짜리 짧은 꼬리였고, 그 안에 "중요 문서(C/S)의 외부 AI 유출을 원천 차단" 같은 문구만 앞뒤 맥락 없이 떨어져 있어 모델이 이것만 보고 S로 판단. 문서 전체 판정은 "여러 구간 중 최고 등급 채택"(N2SF 표 2-9) 규칙이라 이 청크 하나가 전체를 S로 끌어올림.

3-2. 1차 시도 (실패)

짧은 꼬리 청크(100토큰 미만)를 직전 청크에 이어붙이는 방식으로 수정했으나, 합친 길이가 490+100=590토큰이 되어 모델 입력 제한(max_length=512)에 걸려 truncation으로 방금 붙인 꼬리 부분이 다시 잘려나감. 재검증 결과 여전히 S — 근본 원인 해결 안 됨.

3-3. 최종 수정 (적용됨)

마지막 두 청크를 합친 뒤 절반씩 재분배하는 방식으로 변경. 각 청크가 490토큰 이내를 유지하면서도 짧은 꼬리가 충분한 앞 문맥을 갖게 됨. classifier-service/app.py의 _chunk_text() 함수, MIN_TAIL_TOKENS = 200 상수 참고.

if len(boundaries) > 1:
    last_start = boundaries[-1]
    tail_len = total - last_start
    if tail_len < MIN_TAIL_TOKENS:
        merge_start = boundaries[-2]
        half = (total - merge_start) // 2
        boundaries = boundaries[:-2] + [merge_start, merge_start + half]
